# Content Contract — Intertop Training (v1)

## 1. Назначение документа

Это официальный контракт **Content Engine v1** проекта Intertop Training.

- Контент загружается из **filesystem** (каталог `courses/`).
- SQLite хранит пользователей, прогресс обучения и результаты тестов — **не** сами материалы курсов.
- Документ описывает **фактически поддерживаемый** формат на момент текущей версии кода (`app/services/scanner.py`).
- Поля, помеченные как «планируются», в runtime **не поддерживаются** и могут быть проигнорированы scanner.

---

## 2. Реальное дерево курса

```
courses/
  {course_slug}/
    course.json                  # обязателен
    cover.jpg                    # optional (см. поддерживаемые расширения)
    quiz.json                    # optional
    {lesson_slug}/
      lesson.json                # обязателен для распознавания урока
      image.jpg                  # optional (см. поддерживаемые расширения)
      narration.mp3              # optional (см. поддерживаемые расширения)
```

### Пример реального дерева в репозитории

```
courses/
  brands/
    course.json
    quiz.json
    lesson_01/
      lesson.json
      image.jpg
      narration.mp3
  mission/
    course.json
  service/
    course.json
  cashier/
    course.json
```

### Поддерживаемые расширения медиафайлов (scanner)

Scanner ищет **первый существующий файл** с фиксированным именем в указанном порядке:

| Назначение | Имена файлов (порядок проверки) |
|------------|----------------------------------|
| Обложка курса | `cover.jpg`, `cover.jpeg`, `cover.png`, `cover.webp` |
| Изображение урока | `image.jpg`, `image.jpeg`, `image.png`, `image.webp` |
| Озвучка урока | `narration.mp3`, `narration.m4a`, `narration.wav`, `narration.ogg` |

Markdown, YAML, front matter и произвольные имена медиафайлов **не поддерживаются**.

## 3. Course contract

Курс — это подпапка в `courses/` с обязательным файлом `course.json`.

### Идентичность

| Поле | Источник | Описание |
|------|----------|----------|
| `slug` | имя папки курса | Уникальный идентификатор курса. Не берётся из JSON. |

Пример: папка `courses/brands/` → `slug = "brands"`.

### Поля `course.json`

| Поле | Тип | Обязательность | Default / fallback | Пример |
|------|-----|----------------|--------------------|--------|
| `title` | string | optional | имя папки курса | `"История брендов и технологии"` |
| `order` | integer | optional | `9999` | `3` |
| `description` | string | **игнорируется scanner** | — | `"Обязательный курс"` |

Поле `description` может присутствовать в JSON (как в существующих курсах), но **не загружается** в объект `Course` и не используется runtime. Любые другие неизвестные поля также игнорируются.

### Обложка курса

- Файл обложки **optional**.
- Располагается **внутри папки курса**, не в отдельном каталоге.
- Scanner сохраняет путь в `Course.cover_path` или `None`.

### Тест (`quiz.json`)

- Файл **optional**.
- Если файл отсутствует или не содержит ни одного валидного вопроса → `Course.quiz = None`.
- Подробности — в разделах 5 и 6.

### Минимальный пример `course.json`

```json
{
  "title": "История брендов и технологии",
  "order": 3
}
```

## 4. Lesson contract

### Что считается уроком

Уроком считается **подпапка** внутри папки курса, содержащая файл `lesson.json`.

- Папки без `lesson.json` **игнорируются**.
- Файлы напрямую в папке курса (не в подпапках) **не считаются уроками**.

### Идентичность

| Поле | Источник | Описание |
|------|----------|----------|
| slug урока | имя папки урока | Используется в БД (`lessons.slug`) и для сохранения прогресса |

Пример: `courses/brands/lesson_01/` → slug урока = `"lesson_01"`.

### Поля `lesson.json`

| Поле | Тип | Обязательность | Default / fallback | Пример |
|------|-----|----------------|--------------------|--------|
| `title` | string | optional | имя папки урока | `"Rieker"` |
| `description` | string | optional | `""` (пустая строка) | `"История бренда Rieker"` |
| `order` | integer | optional | `9999` | `1` |

### Медиафайлы урока

| Файл | Обязательность | Поведение |
|------|----------------|-----------|
| `image.*` | optional | Отправляется как фото; caption = `description`, если оно непустое |
| `narration.*` | optional | Отправляется как аудио |

### Сортировка уроков

Уроки сортируются по ключу `(order, folder_name)`:

1. поле `order` из `lesson.json` (меньше — раньше);
2. при равном `order` — по имени папки урока (лексикографически).

Порядок отображения в боте определяется **индексом** в отсортированном списке, а не именем папки.

### Минимальный пример `lesson.json`

```json
{
  "title": "Rieker",
  "description": "История бренда Rieker",
  "order": 1
}
```

## 5. Quiz contract

Файл: `{course_slug}/quiz.json`

Scanner загружает тест в объект `Quiz` и присваивает его полю `Course.quiz`. Если загрузка невозможна — `Course.quiz = None`.

### Поля верхнего уровня

| Поле | Тип | Обязательность | Default / fallback | Пример |
|------|-----|----------------|--------------------|--------|
| `id` | string | optional | `"{course_slug}_quiz"` | `"brands_quiz"` |
| `title` | string | optional | `"Итоговый тест"` | `"Итоговый тест"` |
| `passing_score` | integer | optional | `80` | `80` |
| `version` | integer | optional | `1` | `1` |
| `randomize_questions` | boolean | optional | `true` | `false` |
| `randomize_options` | boolean | optional | `true` | `false` |
| `questions` | array | **обязателен для загрузки quiz** | — | см. раздел 6 |

### Правила `passing_score`

- Преобразуется в `int`.
- Допустимый диапазон: **1–100**.
- При отсутствии, некорректном типе или значении вне диапазона → **80**.

Строковые значения `id` и `title` считаются непустыми **после** `strip()`; сохраняется очищенное значение.

### Runtime-поведение полей quiz (важно)

| Поле | Scanner | Runtime handlers |
|------|---------|------------------|
| `passing_score` | парсится и сохраняется в `Quiz.passing_score` | **пока не используется** при подсчёте «сдан/не сдан»; применяется константа `DEFAULT_PASSING_SCORE = 80` в `quiz_repository.finish_attempt()` |
| `randomize_questions` | парсится | **пока не используется** — вопросы показываются в порядке JSON |
| `randomize_options` | парсится | **пока не используется** — варианты показываются в порядке JSON |
| `version` | парсится и сохраняется в `Quiz.version` | записывается в `quiz_attempts.quiz_version` при создании попытки |

## 6. Question contract

Поддерживается только тип **`single_choice`**.

### Поля вопроса

| Поле | Тип | Обязательность | Default / fallback | Пример |
|------|-----|----------------|--------------------|--------|
| `id` | string | **обязателен** | — | `"question_01"` |
| `type` | string | **обязателен** | только `"single_choice"` | `"single_choice"` |
| `text` | string | **обязателен** | — | `"Текст вопроса"` |
| `options` | array | **обязателен** | минимум 2 валидных варианта | см. ниже |
| `correct_option_ids` | array | **обязателен** | ровно 1 id | `["a"]` |
| `explanation` | string | optional | `""` | `"Объяснение ответа"` |
| `lesson` | string | optional | `""` | `"lesson_01"` |
| `difficulty` | integer | optional | `1` | `2` |
| `tags` | array of string | optional | `[]` | `["история", "rieker"]` |
| `ai_context` | string | optional | `""` | `"Контекст для AI"` |

### Поля варианта ответа (`options[]`)

| Поле | Тип | Обязательность |
|------|-----|----------------|
| `id` | string | **обязателен**, непустой после `strip()`, уникален внутри вопроса |
| `text` | string | **обязателен**, непустой после `strip()` |

### Правила валидности вопроса

Вопрос загружается, только если **все** условия выполнены:

1. `type` строго равен `"single_choice"`.
2. `id` — непустая строка после `strip()`; уникален среди всех вопросов теста.
3. `text` — непустая строка после `strip()`.
4. `options` — список с **минимум двумя** корректными вариантами.
5. `id` каждого варианта — непустая строка после `strip()`, уникальна **внутри вопроса**.
6. При **дубликате** `option.id` внутри одного вопроса — **весь вопрос отклоняется**.
7. Некорректные отдельные варианты **пропускаются** (если после фильтрации остаётся ≥ 2 варианта).
8. `correct_option_ids` содержит **ровно один** непустой id после `strip()`.
9. Этот id **существует** среди загруженных вариантов.

Некорректные вопросы **пропускаются** без остановки сканирования курса.

Если после фильтрации не осталось ни одного валидного вопроса → `Course.quiz = None`.

### Обработка `tags`

- Только элементы типа `string`.
- Каждый tag обрезается через `strip()`; пустые строки отбрасываются.

## 7. Runtime behavior

### Загрузка контента

```
courses/ (filesystem)
  → scan_courses() / get_course()  [app/services/scanner.py]
  → Course, Lesson, Quiz (domain objects)
  → handlers (Telegram UI)
  → sync_courses() при старте  [app/services/course_sync.py]
  → SQLite (courses, lessons — метаданные и пути)
```

- `scan_courses(base_dir)` — возвращает список курсов, отсортированных по `(order, slug)`.
- `get_course(base_dir, slug)` — ищет курс по slug; каждый вызов **пересканирует** каталог (кэша нет).
- Каждый `Course` **всегда** имеет поле `quiz: Quiz | None`.

### Tolerant loading (устойчивость к ошибкам)

#### Отсутствие обязательного JSON-файла

| Ситуация | Поведение |
|----------|-----------|
| Папка курса без `course.json` | Курс **не загружается** (`_scan_course` → `None`) |
| Подпапка без `lesson.json` | **Не считается уроком** (`_scan_lesson` → `None`) |
| Отсутствие `quiz.json` | `Course.quiz = None` |

#### Существующий, но повреждённый или невалидный JSON

`_read_json()` перехватывает `OSError` и `json.JSONDecodeError`, а также отвергает не-dict корень; в этих случаях возвращается `{}`.

| Файл | Поведение |
|------|-----------|
| `course.json` существует, но не читается или содержит невалидный JSON | Курс **загружается** с fallback-значениями: `title` = имя папки, `order` = `9999` |
| `lesson.json` существует, но не читается или содержит невалидный JSON | Подпапка **считается уроком** с fallback-значениями: `title` = имя папки, `description` = `""`, `order` = `9999` |
| `quiz.json` существует, но не читается или содержит невалидный JSON | `Course.quiz = None` (пустой объект после `_read_json`) |
| `quiz.json` читается, но структура некорректна или нет валидных вопросов | `Course.quiz = None` |

#### Прочие случаи

| Ситуация | Поведение |
|----------|-----------|
| Невалидные вопросы в `quiz.json` | Пропускаются по одному |
| Quiz без валидных вопросов после фильтрации | `Course.quiz = None` |
| Отсутствие медиафайлов | `cover_path`, `image_path`, `narration_path` = `None`; бот работает без них |

**Ожидаемые ошибки чтения JSON и невалидный контент обрабатываются мягко; приложение продолжает работу.**

### Синхронизация с БД

- `sync_courses()` вызывается **один раз при старте** (`app/main.py`).
- Метаданные курсов и уроков записываются в SQLite по slug.
- После **изменения структуры уроков** (добавление, удаление, переименование папок) может потребоваться **перезапуск приложения** для корректной синхронизации прогресса.
- Изменения в JSON-контенте (тексты, quiz) подхватываются при следующем вызове `get_course()` / `scan_courses()` **без перезапуска**, но sync в БД обновится только после перезапуска.

## 8. Sorting and identity rules

### Course slug

- Определяется **только** именем папки: `courses/{course_slug}/`.
- Используется в callback_data, прогрессе, quiz attempts.
- **Переименование папки курса** после публикации разрывает связь с сохранённым прогрессом и историей тестов.

### Lesson slug

- Определяется **только** именем папки урока.
- Сохраняется в БД и привязывается к прогрессу пользователя.
- **Переименование папки урока** после публикации делает старый прогресс «осиротевшим» — пользователь может потерять отметки о прохождении.

### Course ordering

- Поле `order` в `course.json` (default `9999`).
- При равном `order` — сортировка по `slug` (имени папки).

### Lesson ordering

- Поле `order` в `lesson.json` (default `9999`).
- При равном `order` — сортировка по имени папки урока.

### Почему переименование опасно

Прогресс и enrollments в SQLite ссылаются на slug курса и slug урока, записанные при `sync_courses()`. Scanner определяет slug из **текущего** имени папки. Несовпадение имён → рассинхронизация прогресса.

## 9. Author checklist

Перед публикацией курса проверьте вручную:

- [ ] Папка курса имеет осмысленный slug (латиница, без пробелов).
- [ ] Файл `course.json` существует и содержит корректный `title`.
- [ ] Каждый урок — отдельная подпапка с `lesson.json`.
- [ ] У всех уроков задан уникальный `order` (или осознанный fallback `9999`).
- [ ] Медиафайлы названы строго: `cover.jpg`, `image.jpg`, `narration.mp3` (или другие поддерживаемые расширения).
- [ ] Если есть `quiz.json` — каждый вопрос типа `single_choice`, минимум 2 варианта, один правильный ответ.
- [ ] Id вопросов уникальны; id вариантов уникальны внутри каждого вопроса.
- [ ] После добавления/удаления/переименования уроков — перезапустить бота для sync прогресса.
- [ ] Пройти курс и тест в боте end-to-end.

## 10. Future fields — not implemented

Следующие возможности **запланированы**, но **не являются частью runtime-контракта v1** и не должны добавляться в контент как обязательные поля:

| Поле / концепция | Статус |
|------------------|--------|
| `content_version` | планируется |
| `status`: `draft` / `published` | планируется |
| Расширенные AI-метаданные (генерация, ревью) | планируется |
| Tenant namespace / multi-tenancy | планируется |
| Markdown / YAML / front matter | **не используются** |
| Scanner cache | **не реализован** |

Добавление этих полей в JSON **не сломает** scanner (неизвестные поля игнорируются), но **не изменит** поведение приложения до отдельной реализации.
